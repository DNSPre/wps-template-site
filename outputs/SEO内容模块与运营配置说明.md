# 详情与分类 SEO 内容补充

2026年10月26日

## 本次实现

- 详情：资源预览及操作之后、相关资源之前，增加资源说明卡、特点与规格、包含内容、4项常见问题及相关主题链接。特点和内容清单使用原生折叠交互；FAQ 默认收起，支持键盘。
- 分类与标签：在列表及分页下方增加主题介绍、选择指南、使用步骤、相关主题和3项常见问题。参考 CapCut 的“先资源，后 About”顺序，不在列表前堆长篇文字。
- 简历、求职信、预算、考勤、薪资、收支、库存，以及八个任务大类提供中英文主题专属说明。其他界面语言按资源类型和本地提示生成说明，不回退整段英文；上线前仍需母语审校。
- 六种资源类型都有说明和 FAQ；模板概念、真实 SVG、字体及会员演示素材使用不同的格式和权限说明。不承诺未经验证的 ATS、AI 编辑、税务合规或并不存在的 Office 原文件。
- 主题链接使用真实 a href，并能直接恢复类型、分类和子任务，例如 /en-us/resources/?type=templates&category=career&task=resume 。切换筛选同步维护该组参数。
- 对应页面的浏览器标题和 description 随主题或资源更新。未添加 meta keywords，也不以隐藏词堆砌代替内容。

## 可维护内容结构

当前文案位于 work/seo-content-v28.js。seoLabels28 管理17种语言公共文案，seoTypeDescriptions28 管理6类资源说明，seoTaskDescriptions28 管理具体任务及分类的专属说明。资源名称、格式、文件语言、权益和许可仍读取同一资源目录，避免两套说明冲突。

正式 CMS 建议支持 resourceId 或 topicId、locale、标题、用途摘要、正文、特点、包含内容、FAQ问答、相关主题、主关键词、目标query、审核状态及更新时间。关键词和目标query是运营编辑字段，不直接生成可见的关键词堆叠。每个页面需围绕真实需求编辑独立内容，不以改标题批量复制相同段落。

资源内容必须与真实文件、版本和许可一致；未知的页数、文件大小、兼容性和AI能力不补写。FAQ回答应清楚区分免费浏览、会员使用、原文件可用性和编辑能力。

## 搜索收录边界

本轮补齐可见的设计及内容模块、原生主题链接、客户端标题和description。当前服务仍是 JavaScript 原型；详情沿用 hash 资源链接。添加这些模块不等于已完成生产 SEO 收录，也不承诺查询排名。

正式上线还需稳定的可抓取详情URL、标签规范地址、服务端渲染或静态预渲染、canonical、hreflang、sitemap 和组合筛选索引策略。新增主题参数用于交互验证，不应自动将每种筛选组合都作为独立可索引页面。FAQ结构化数据需在真实内容和页面符合要求时另行评审，本轮不添加保证富结果的标记。
